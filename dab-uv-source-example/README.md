# DAB + uv + pyproject.toml — No Wheel Build

This Declarative Automation Bundle deploys Python **source files** directly
to the workspace. There is no wheel artifact — the package version and
dependencies are managed entirely through `pyproject.toml` + `uv`.

## How it works

1. **`pyproject.toml`** is the single source of truth for:
   - Package version (`version = "0.3.1"`)
   - Runtime dependencies (`dependencies = ["pandas>=2.0", ...]`)
   - Dev dependencies (`[dependency-groups] dev = [...]`)

2. **No `artifacts` section** in `databricks.yml` → no wheel is built
   during `bundle deploy`. Source `.py` files are synced as-is.

3. **Pipeline deps** are installed at runtime via:
   ```yaml
   environment:
     dependencies:
       - --editable ${workspace.file_path}
   ```
   This reads `pyproject.toml` from the deployed workspace path and
   installs the package + all its dependencies in the pipeline environment.

4. **Job deps** use the same pattern via `environment_key` + `environments`:
   ```yaml
   tasks:
     - task_key: run_main
       notebook_task:
         notebook_path: src/main_notebook.py
       environment_key: default

   environments:
     - environment_key: default
       spec:
         environment_version: "1"  # serverless base environment
         dependencies:
           - --editable ${workspace.file_path}
   ```
   On serverless compute, `libraries` is not supported on tasks — deps
   must go in the `environments` block. The `--editable` install reads
   `pyproject.toml` at task startup, just like the pipeline.

## Local development

```bash
# Install uv (if not already installed)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Create venv and install all deps
uv sync

# Run tests
uv run pytest

# Lint
uv run ruff check src/

# Deploy to dev
databricks bundle deploy --target dev

# Run the pipeline
databricks bundle run --target dev etl_pipeline

# Run the job (notebook task)
databricks bundle run --target dev daily_job
```

## Bumping the version

Edit the `version` field in `pyproject.toml`:

```toml
[project]
version = "0.4.0"   # <-- bump here
```

Then redeploy. The new version is picked up at runtime via
`importlib.metadata.version("dab-uv-source-example")`.

## Project structure

```
dab-uv-source-example/
├── databricks.yml          # Bundle config (no artifacts section)
├── pyproject.toml          # Version + deps (managed by uv)
├── uv.lock                 # Generated by `uv lock` (commit this)
├── README.md
└── src/
    ├── main_notebook.py    # Job notebook entry point (# Databricks notebook source format)
    └── transformations/
        ├── __init__.py     # Reads version from pyproject.toml
        └── etl.py          # Pipeline source file with @dlt.table definitions
```
